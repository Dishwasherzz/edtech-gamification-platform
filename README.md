# Cybervolt

Образовательная платформа с элементами геймификации по дисциплине «Электротехника».
Студент изучает лекции, проходит босс-тесты или сценарии аварий (QTE), получает опыт и монеты.

**Сайт:** [cybervolt.red.tpu.ru](https://cybervolt.red.tpu.ru/)

## Стек

- Бэкенд: C#, ASP.NET Core / .NET 10, Entity Framework Core 10.
- База данных: PostgreSQL 18.
- Фронтенд: HTML, CSS, JavaScript; файлы раздаёт приложение ASP.NET Core вместе с API.
- Развёртывание: Docker Compose, GitHub Actions, GHCR и systemd на Ubuntu.

## Возможности бэкенда

- Регистрация, вход и выход, профиль, выбор героя, смена ника и пароля, восстановление доступа и удаление аккаунта. Аутентификация через cookie с CSRF-защитой.
- Курс из восьми тем: в темах 1–7 есть лекции, 92 вопроса и 21 сценарий QTE; тема 8 пока доступна для чтения и завершается отметкой «Прочитано». Темы открываются последовательно.
- Босс-тесты и QTE с серверными таймерами, проверкой ответов, сохранением попыток и разбором результатов.
- XP, разряды, монеты, бонусы, ограничения повторных наград, история прохождения и итог курса.
- API маскотов и их реакций, скинов, гардероба и покупок за монеты с защитой повторных запросов.
- Миграции БД, интеграционные тесты, OpenAPI в режиме разработки и проверки состояния приложения.

Параметры наград и разрядов находятся в секции `Game` файла [appsettings.json](src/EducationGamePlatform/appsettings.json).
Для писем восстановления доступа нужен SMTP. Текст согласия пока черновой; учебные материалы требуют согласования с преподавателем.
Настройки аккаунтов и учебного пакета описаны в [инструкции по интеграции](docs/analyst-integration.md).

## Локальный запуск

Нужны .NET SDK 10 и доступная база PostgreSQL. Команды ниже выполняются в PowerShell из корня репозитория.

1. Настрой подключение к своей БД по [инструкции](docs/local-database.md). Скрипт `scripts/Set-LocalDatabase.ps1` проверяет подключение и сохраняет его в `src/EducationGamePlatform/appsettings.Local.json`; адрес, порт, имя базы и пользователя можно передать параметрами. База и пользователь должны уже существовать.
2. При первой настройке или обновлении схемы/учебного пакета выполни:

   ```powershell
   .\scripts\Start-Api.ps1 -Migrate -SeedAnalyst
   ```

3. Запусти приложение:

   ```powershell
   .\scripts\Start-Api.ps1
   ```

Открой [http://localhost:5244/](http://localhost:5244/). Отдельный сервер фронтенда и npm не нужны.
В Rider можно открыть `EducationGamePlatform.sln` и использовать профиль `http` вместо шага 3.
Обычный запуск не применяет миграции и не загружает учебные данные автоматически.

- Готовность приложения и БД: [http://localhost:5244/health/ready](http://localhost:5244/health/ready).
- Контракт OpenAPI в Development: [http://localhost:5244/openapi/v1.json](http://localhost:5244/openapi/v1.json).
- Запуск через Docker: [инструкция](docs/deployment.md).

Локальная конфигурация и `deploy/.env` исключены из Git. Пароли, ключи и резервные копии в репозиторий не добавлять.

## Проверки и автодеплой

GitHub Actions проверяет сборку, миграции, интеграционные тесты, конфигурацию Compose и запуск Docker-образа.
После успешных проверок коммита в `main` публикуется образ в GHCR.

На настроенном сервере `edtech-deploy.timer` запускает проверку обновлений через 2 минуты после загрузки и затем через 5 минут после завершения предыдущего запуска сервиса. Новая версия устанавливается из образа: резервная копия БД → миграции и учебные данные → запуск → проверка готовности.
Это опрос сервера, поэтому публикация коммита не означает мгновенное обновление сайта.
Изменения файлов Compose, скрипта обновления и systemd нужно переносить на сервер отдельно.

- [Установка и обслуживание автодеплоя](docs/deployment.md#автодеплой-на-ubuntu).
- [Сборка, миграции и запуск тестов](docs/development.md). Тестам нужен отдельный PostgreSQL/пользователь с правом создания временных баз.

## Структура репозитория

```text
frontend/            интерфейс и API-клиент
src/EducationGamePlatform/
  Domain/            сущности
  Features/          аккаунты, каталог, испытания, прогресс и косметика
  Infrastructure/    инфраструктура приложения
  Persistence/       EF Core, миграции и учебные данные
tests/               интеграционные тесты
docs/                техническая документация
requests/            примеры HTTP-запросов для Rider
scripts/             настройка подключения и запуск на Windows
deploy/              Docker, Compose и автодеплой
.github/workflows/   проверки и публикация образа
```
