# Пакет аналитика и новые API

## Учебный контент

Из корня репозитория на Windows запусти `.\scripts\Start-Api.ps1 -Migrate -SeedAnalyst`, затем `.\scripts\Start-Api.ps1`. При запуске в Linux передай `--migrate --seed-analyst` приложению с настроенным подключением к нужной БД.

Пакет включает 8 лекций, 92 вопроса босс-теста и 21 сценарий QTE по 4 шага для тем 1–7. В темах 1–3 по 12 вопросов, в темах 4–7 по 14. Шесть сюжетов тем 1–3 пришли от аналитика. Для темы Кирхгофа добавлены три симуляции на баланс токов, напряжений и мощностей. Вопросы 160, 163, 174 и 178 уточнены по условиям с сохранением ключей ответов.

Лекции 4–8 добавлены 26 ноября 2026 года: синусоидальный ток, комплексные законы Ома и Кирхгофа, резонанс, взаимная индуктивность и трансформатор, трёхфазные цепи. Markdown хранится в `src/EducationGamePlatform/Persistence/Content/Lectures/` и входит в сборку. `--seed-analyst` добавляет или обновляет лекции даже в базе с уже установленным пакетом испытаний. Повторный импорт сохраняет ID, отметки чтения, награды и историю. Тема 8 без опубликованных испытаний завершается прочтением всех лекций, без награды за победу. За первое прочтение начисляются обычные 20 XP. Следующая тема открывается последовательно. Процент курса рассчитывается по восьми темам. Схема БД не меняется.

Испытания тем 4–5 перенесены из документов `Тема_4_тесты_и_QTE.docx` и `Тема_5_тесты_и_QTE.docx` в `Persistence/Content/AdditionalTrials.json`. Сохранены исходные ID заданий, варианты ответов, разборы и описания иллюстраций. Босс выбирает 7 из 14 вопросов, 50 секунд на вопрос. QTE — прогноз изменений характеристик виртуальной цепи: 3 сценария, по 4 шага и 3 варианта, 60 секунд с изменением на +10/−10 секунд. Порядок вариантов каждого шага фиксирован, но верный ответ не всегда первый. Новые правила наград не вводились.

Если все лекции темы были прочитаны до первой публикации её испытаний, статус завершения сохраняется без создания фиктивной попытки и начисления награды за победу. Новое прочтение после публикации испытаний открывает допуск, но завершение требует победы. История и XP за лекции сохраняются.

По замечаниям из документа исправлены два знака в лекции 5: второе слагаемое разложения мгновенной мощности положительное, а потенциал при переходе по току через конденсатор возрастает на `j I X_C`. Файлы иллюстраций в приложенных документах отсутствуют: сохранены описания для дизайнеров; используются существующие схемы-заглушки. Локальные ссылки `file:///C:/...` в лекциях 4–5 остаются вопросом к автору материалов, а не ссылками на доступные серверные изображения.

Импорт обновляет лекции и создаёт новые версии испытаний. Незавершённые и законченные попытки хранят ссылку на исходную версию вопросов. Идентификаторы тем и лекций, отметки чтения, открытия тем и начисленные награды сохраняются. Повторная загрузка пакета пропускает уже установленные версии.

QTE описывают действия в учебной симуляции. Сценарии с поражением током, оборванным проводом и дымом адаптированы к виртуальному стенду и требуют проверки преподавателем перед публикацией. ## Контракты для интерфейса

| Запрос | Данные и результат |
| --- | --- |
| `GET /api/auth/registration` | Два героя, герой по умолчанию, минимум пароля, статус регистрации и текущий текст согласия с версией |
| `POST /api/auth/register` | `email`, `password`, `displayName`, `heroKey` (по умолчанию `phase`), `acceptConsent`, `consentVersion`. С `signIn: true` сразу устанавливает cookie |
| `GET /api/me` | Дополнительно возвращает свой email, героя, версию и дату согласия, XP до следующего разряда |
| `PUT /api/me/nickname`, `PUT /api/me/hero` | `displayName` или `heroKey`. Успех — 204 |
| `PUT /api/me/password`, `DELETE /api/me` | `currentPassword` и `newPassword` либо `password` для удаления. Успех — 204 |
| `POST /api/auth/forgot-password` | `email`. При настроенной почте ответ 202 одинаковый для существующих и неизвестных адресов |
| `POST /api/auth/reset-password` | `userId`, `token`, `newPassword`. Успех — 204. Ссылка действует час и перестаёт работать после смены пароля |
| `GET /api/instructions`, `GET /api/public/courses`, `GET /api/public/courses/{courseId}/topics` | Публичная инструкция и карточки тем. Для лекций, прогресса и испытаний нужен вход |
| `GET /api/me/courses/{courseId}/journey` | `destination` (`Attempt`, `Lesson`, `Topic`, `Completed` или `Topics`), нужные ID и итоговая статистика для завершённого курса |
| `POST /api/me/courses/{courseId}/completion/claim` | После прохождения курса 200 со статистикой для первого вызова, 204 для повторных, 409 до завершения |

У попытки дополнительно есть `bossIcon`, `bossIntro`, `currentQuestion.calculationHint`, `nextTopicId` и `completedCourseId`. Для новой победы с повышением сервер возвращает `reward.newRank`. Срок ответа берётся из `currentQuestion.expiresAt`. В новых босс-тестах это 50 секунд, старые попытки используют прежние настройки.

Изменяющие запросы требуют cookie CSRF и заголовок `X-CSRF-TOKEN` из `GET /api/auth/csrf`. Обновляй токен после изменения сессии. Герой хранится отдельно от выбранного маскота и экипированного скина.

## Настройки запуска

- В обычном окружении регистрация требует согласие. Для пилота сервер выдаёт черновик `2026-11-14-draft` из `appsettings.json`. Когда текст утвердят, задай новую версию и текст через `Account__ConsentVersion` и `Account__ConsentText`. Если задан только один параметр, регистрация возвращает 503. В `Development` проверка по умолчанию отключена. Старые ники сохранены, новые и изменённые проверяются на уникальность без учёта регистра.
- Для почты укажи `PasswordMail__Host`, `PasswordMail__Port` (по умолчанию 587), `PasswordMail__From`, при необходимости `PasswordMail__Username` и `PasswordMail__Password`. SMTP должен поддерживать STARTTLS. `PasswordMail__ResetPageUrl` указывает на HTTPS-страницу сброса. Ссылка передаёт `userId` и `token` во фрагменте. Почтовая очередь хранится в памяти процесса. В Docker передай переменные в окружение сервиса API.
- Удаление удаляет аккаунт и связанные записи из рабочей базы и завершает сессии. Политика хранения резервных копий настраивается при развёртывании.
- Формы регистрации, восстановления и настроек используют эти контракты. Клиент обрабатывает гостевой каталог, выбор героя и итог курса, а лекции отображает через Markdown с поддержкой формул.

28 ноября 2026 года добавлены ещё 28 вопросов и 6 QTE-сценариев из документов аналитика. Уточнены условия задач и допущения виртуальных стендов, исправлены связанные неточности лекций. Ответы пересчитаны; проверка чисел и знаков включена в тесты. Подробная сверка с лекциями и перечень изменений: [отчёт](content-review-topics-6-7.md). Существующие версии испытаний тем 1–5 не меняются. Пройденные ранее чтением темы 6–7 сохраняют статус; для новых прохождений после чтения нужна победа. Параметры таймеров и наград прежние.
