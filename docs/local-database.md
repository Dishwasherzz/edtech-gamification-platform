# Локальная база EducationGamePlatform

Используется существующий PostgreSQL 18:

- адрес: `localhost`;
- порт: `5434`;
- база: `EducationGamePlatform` — сохранить точное написание;
- владелец базы в pgAdmin: `postgres`;
- отдельный пользователь приложения: `education_game_platform_app`.

База находится в установленном PostgreSQL, а не в репозитории и не в Docker.
В pgAdmin: PostgreSQL 18 → Databases → EducationGamePlatform → Schemas → public → Tables.
После миграции обновить дерево через Refresh.

## Когда пароль postgres неизвестен

Если pgAdmin уже подключён как `postgres`, через Query Tool для **EducationGamePlatform**
можно создать отдельного пользователя приложения и дать ему CONNECT к этой базе и CREATE/USAGE
в схеме public. Ему не нужны SUPERUSER, CREATE DATABASE и права управления другими пользователями.
При первичном подключении локальный SQL-скрипт с такими командами подготовлен вне Git.
Пароль `postgres` и настройки аутентификации сервера при этом не меняются.

Файл со сгенерированным паролем доступа держать только на своём ПК, не публиковать.
Миграции создают таблицы от пользователя приложения; он становится их владельцем.
Если таблицы ранее созданы другим пользователем, отдельно согласовать владельца и права
перед обновлением схемы. Нельзя просто удалять существующие таблицы ради миграции.

## Настройка подключения

Из корня репозитория:

```powershell
.\scripts\Set-LocalDatabase.ps1
```

Скрипт запросит пароль скрытым вводом, проверит подключение и сохранит
`src/EducationGamePlatform/appsettings.Local.json`, который исключён из Git и Docker.
При неверном пароле предыдущая настройка останется без изменений.
Для своего пользователя использовать `-DatabaseUser postgres` или другое имя.

Development читает конфигурацию в порядке приоритета: аргументы командной строки →
переменные окружения → `appsettings.Local.json` → user-secrets → обычные appsettings.
Production не читает `appsettings.Local.json`; на сервере строка задаётся через окружение.
Локальный файл позволяет Rider и терминалу использовать одно подключение независимо
от профиля Windows, под которым записаны user-secrets.

## Таблицы и запуск

Для пустой базы после настройки подключения:

```powershell
.\scripts\Start-Api.ps1 -Migrate -SeedDemo
.\scripts\Start-Api.ps1
```

Первый запуск создаёт таблицы Identity и 14 предметных сущностей, добавляет курс,
тему и лекцию. Второй запускает API. Повтор миграции и демоданных не создаёт дублей.
В Rider можно вместо второго шага выбрать профиль `EducationGamePlatform: http`.

Проверка: `http://localhost:5244/health/ready` → `Healthy`.
Примеры запросов — [EducationGamePlatform.http](../requests/EducationGamePlatform.http).

## Перенос из предыдущей базы

Предыдущая база `edtech` была подготовлена отдельно на порту `55489`.
10 октября 2026 года её данные перенесены в `EducationGamePlatform` на порту `5434`:
21 таблица (включая Identity и историю миграций), один пользователь с профилем,
курс, тема, лекция и отметка чтения. Содержимое всех таблиц сверено с источником.
Проверены регистрация, вход, профиль, каталог, чтение, повтор отметки и выход через API.
Временный проверочный аккаунт удалён. Исходная база и резервные копии сохранены вне Git.

Миграция, модели и существующие маршруты остались прежними; новые игровые функции при переносе не добавлялись.

При переносе сначала сохранить её резервную копию вне Git и проверить, что целевая база пуста.
Применить исходную миграцию к цели, затем импортировать данные с сохранением идентификаторов,
пользователей и отметок чтения в одной транзакции. Данные в целевой базе не перезаписывать.
После этого повторная загрузка демоданных проверит их наличие без дублей.

Для существующей заполненной цели нужен отдельный план объединения данных.
Тесты не запускать прямо на этой рабочей БД: им нужен отдельный сервер/пользователь
с правом CREATE DATABASE, они используют временные базы со случайными именами.
