# План обучения: от циклов до понимания своего API

> План составлен для первоначального каркаса. Теперь игровые функции также реализованы:
> после базовых упражнений переходи к [GameService и интеграции](trials-and-integration.md).
> Упражнения на классы, LINQ, HTTP, профиль и EF Core остаются применимы.

Твоя исходная точка: массивы и циклы уже знакомы, C# и веб-бэкенд ещё нужно освоить. Цель этого плана — научиться объяснять и самостоятельно менять существующий EducationGamePlatform. Первые упражнения делай в отдельной консольной программе, затем переходи к настоящему API.

Это 12 этапов, а не обещание освоить всё за 12 дней. Этап может занять несколько занятий. Для начала подходит занятие на 45–90 минут: немного теории, больше самостоятельного кода, в конце объяснение результата своими словами. Переходи дальше, когда можешь повторить упражнение без копирования.

## 12 этапов с конкретным результатом

| Этап | Что изучить | Что сделать | Признак понимания |
|---|---|---|---|
| 1 | Методы: параметры, возвращаемое значение, `void`, `return` | Написать метод расчёта тока `CalculateCurrent(voltage, resistance)` и вызвать несколько раз; отдельно продумать нулевое сопротивление | Можешь объяснить входные данные и результат без слова «магия» |
| 2 | Класс, объект, свойства, `new`, конструктор | Выполнить первое упражнение ниже, создать несколько объектов курса | Различаешь тип и конкретный экземпляр |
| 3 | `public/private`, `static`, наследование, интерфейс | Найти наследование `ApplicationUser`, разобрать простую собственную пару базового и дочернего классов; интерфейс изучить на маленьком примере | Понимаешь двоеточие после имени класса и зачем скрывать детали |
| 4 | `List<T>`, словарь, `enum`, `Guid`, `null`, `?` | Создать список лекций, статус публикации и необязательную дату чтения | Можешь объяснить основные свойства в `Domain/Course.cs` |
| 5 | Лямбды и LINQ: `Where`, `Select`, `OrderBy`, `Any`, `Count` | На списке в памяти выбрать названия опубликованных курсов; сравнить с циклом | Читаешь каждое звено цепочки отдельно |
| 6 | `Task`, `async/await`, исключения, `using`, `CancellationToken` | В отдельной программе написать асинхронный метод с `await Task.Delay(100)` и проследить порядок вывода | Понимаешь ожидание; не воспринимаешь `async` как запуск отдельного потока |
| 7 | HTTP, URL, JSON, заголовки, статусы, DTO и `record` | Пройти готовый `.http`-сценарий; записать метод, адрес и статус каждого запроса | Отличаешь 200/201/204/400/401/404 и тело запроса от ответа |
| 8 | ASP.NET Core, Minimal API, DI и middleware | Разобрать `Program.cs`: отметить `Add`, `Use`, `Map`; затем прочитать маршрут профиля | Объясняешь, кто передаёт `AppDbContext` в обработчик и когда он выполняется |
| 9 | SQL: `SELECT`, `WHERE`, `JOIN`; ключи и связи | Посмотреть профиль и отметку чтения в pgAdmin, выполнить запросы из руководства | Различаешь данные в памяти и строки PostgreSQL |
| 10 | EF Core, `DbContext`, tracking, `SaveChangesAsync`, миграции | Проследить `GET /api/me` от LINQ до ответа, затем регистрацию от `Add` до сохранения | Знаешь, когда выполняется SQL и почему новое свойство не создаёт колонку само |
| 11 | Identity, хеш пароля, cookie, claims, CSRF, транзакция | Объяснить регистрацию и вход по коду; увидеть 401 после выхода и 400 без CSRF | Различаешь учётную запись, аутентификацию и защиту изменяющего запроса |
| 12 | Отладка, тесты и небольшое изменение контракта | Добавить учебное вычисляемое поле в DTO профиля, проверить ответ, обновить карту API; прочитать один существующий тест | Можешь внести изменение и объяснить, какие файлы и поведение затронуты |

Темы сложнее начального уровня не нужно сразу понимать во всех деталях. Например, на первом чтении Identity достаточно знать, что `UserManager` создаёт пользователя с хешем пароля, а `SignInManager` проверяет вход и управляет cookie. Алгоритмы хеширования и внутреннее устройство EF Core можно разобрать позже.

## Первое занятие: объект курса и список

Создай в Rider отдельный **Console Application** на .NET 10 за пределами репозитория бэкенда, например в `C:\Users\kosti\RiderProjects\CSharpPractice`. В его `Program.cs` помести этот самостоятельный пример. Рабочий `Program.cs` API не заменяй.

```csharp
List<StudyCourse> courses = new List<StudyCourse>
{
    new StudyCourse { Title = "Закон Ома", IsPublished = true },
    new StudyCourse { Title = "Черновик лекции", IsPublished = false },
    new StudyCourse { Title = "Мощность тока", IsPublished = true }
};

foreach (StudyCourse course in courses)
{
    if (course.CanRead())
        Console.WriteLine(course.Title);
}

public class StudyCourse
{
    public string Title { get; set; } = "";
    public bool IsPublished { get; set; }

    public bool CanRead()
    {
        return IsPublished;
    }
}
```

Ожидаемый вывод:

```text
Закон Ома
Мощность тока
```

Проверь себя небольшими изменениями:

1. Сделай черновик опубликованным. Предскажи вывод до запуска.
2. Добавь четвёртый курс. Объясни, сколько объектов создано.
3. Убери вызов метода и проверь непосредственно `course.IsPublished`. Сравни поведение.
4. Объясни, чем переменная `courses` отличается от `course` внутри цикла.
5. Верни исходные значения и напиши пример заново без подсказки.

После этого открой [Course.cs в бэкенде](../src/EducationGamePlatform/Domain/Course.cs). Узнай знакомые `Title`, `IsPublished`, `get`, `set`, `List<T>`. Пока достаточно понять свойства: подключение базы будет отдельным этапом.

## Как привязывать теорию к проекту

После каждой темы находи **один** пример в своём коде:

| Теория | Твой пример |
|---|---|
| Класс и свойства | `Course`, `Lesson` |
| Наследование | `ApplicationUser : IdentityUser<Guid>` |
| Обобщения | `List<Topic>`, `DbSet<Lesson>` |
| Nullable | `CompletedAt` в ответе лекции: отметки ещё может не быть |
| Enum | `AssessmentMode`, `AttemptStatus` |
| Record / DTO | `ProfileResponse`, `LoginRequest` |
| Лямбда и LINQ | `Where` и `Select` в получении профиля |
| Async / await | `SingleOrDefaultAsync`, `PasswordSignInAsync` |
| DI | `AppDbContext database` в параметрах обработчика |
| Транзакция | `RegisterAsync`: пользователь и профиль сохраняются вместе |
| Ограничение уникальности | Первичный ключ `LessonProgress` и повторная отметка |
| Интеграционный тест | Сценарий регистрации и входа в `ApiTests.cs` |

Для каждого выбранного метода заполняй небольшой конспект:

```text
Метод / маршрут:
Какие данные получает:
Какие сервисы использует:
Что проверяет:
Что читает или меняет в БД:
Что возвращает при успехе:
Какие ошибки возможны:
Как я это проверил:
```

Пример для профиля: `GET /api/me`; использует проверенного пользователя и `AppDbContext`; читает его запись из `PlayerProfiles`; возвращает DTO с именем и счётчиками; без входа — 401, без профиля — 404. Проверка — запрос в Rider и просмотр переменных в отладчике.

Когда читаешь цепочку из пяти LINQ-методов, перепиши её в конспекте пятью короткими действиями. Когда встречаешь незнакомую конструкцию языка, отдельно выполни её маленький пример в консольной программе. Это уменьшает число новых вещей, которые нужно держать в голове одновременно.

## Когда можно считать первую цель достигнутой

Ты готов самостоятельно поддерживать текущий каркас, когда можешь без пошаговой подсказки:

- запустить API и отличить проблему приложения от проблемы подключения к БД;
- пройти регистрацию → вход → профиль → лекцию → отметку → выход;
- объяснить, почему ID пользователя берётся из cookie и почему повтор отметки не создаёт дубль;
- найти обработчик маршрута, DTO, сущность и её конфигурацию;
- остановиться на breakpoint и сопоставить результат с записью в PostgreSQL;
- добавить вычисляемое поле ответа и объяснить, почему миграция не требуется;
- назвать функции, которые ещё не реализованы, несмотря на готовые таблицы.

Следующая учебная цель — добавление сохраняемого поля с новой миграцией на отдельной учебной БД. После неё можно планировать один небольшой сценарий прохождения теста. Docker, развёртывание на Ubuntu, сложные архитектурные шаблоны и полный игровой движок оставь до уверенного понимания этого пути.
