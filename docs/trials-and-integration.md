# Испытания и интеграция фронтенда

Реализация от 17 октября 2026 года следует документу «Логика учебного испытания» и требованиям с доски.
Основной путь: вход → теория → «Прочитано» → выбор одного из двух испытаний → результат → следующая тема.
Фронтенд и API запускаются одной командой; никакой фиктивной авторизации или начисления очков в JavaScript нет.

## Запуск после обновления

Перед применением миграций к заполненной БД сохранить резервную копию. Затем из корня репозитория:

```powershell
.\scripts\Start-Api.ps1 -Migrate -SeedDemo
.\scripts\Start-Api.ps1
```

Открыть `http://localhost:5244/`. Если база уже настроена, пароль заново вводить не нужно.
Старые аккаунты и отметки чтения сохраняются. Старой отметке без начисленного XP можно один раз выдать новую награду,
повторив подтверждение через API или кнопкой «Подтвердить прочтение»; новые отметки сразу начисляют XP. Уже сохранённое время чтения не меняется.

## Правила

| Событие | Поведение |
|---|---|
| Прочтение | 20 XP один раз на лекцию; все опубликованные лекции темы должны быть отмечены |
| Доступ к теме | Первая открыта, следующие — после победы в предыдущих опубликованных темах |
| Выбор режима | Два режима равноценны для завершения темы; одновременно разрешена одна активная попытка пользователя |
| Босс | 7 вопросов из банка, 4 варианта; 5 верных дают победу, третья ошибка даёт поражение |
| Таймер босса | 45–60 секунд по настройке версии; в демо 60. Пропуск считается ошибкой, следующий вопрос начинается с предыдущего дедлайна |
| Авария | 1 из 3 сценариев, 4 шага, 3 действия; неверное действие блокируется, остальные доступны на том же шаге |
| Таймер аварии | 60 секунд после «Действовать», +10 за верный выбор, −10 за неверный; 4 верных шага дают победу, третья ошибка или нулевой отсчёт — поражение |
| Первая победа по теме | 100 XP / 30 монет, независимо от режима |
| Без ошибок при первой победе | Ещё 50 XP / 20 монет; бонус не выдаётся задним числом за повтор |
| Повторная победа | 25% базовой награды с округлением вниз: 25 XP / 7 монет; бонуса нет |
| Поражение | Нулевая награда, баланс не уменьшается, ранее завершённая тема остаётся завершённой |
| Итоги | У босса разбор предъявленных вопросов, у QTE — вся последовательность из 4 шагов с объяснениями |
| Повтор | Сначала невиденные вопросы; QTE сначала невиденные сценарии, с исключением предыдущего, когда доступна альтернатива |
| Конец курса | На главной показывается 100% и сообщение о завершении; повторение остаётся доступным |

Подготовленный вводный экран QTE не расходует игровой таймер. Если его бросить на 30 минут, подготовка завершается как истёкшая.
После начала игры закрытие вкладки и обновление страницы не останавливают время.
Фоновый обработчик раз в секунду завершает истёкшие попытки без участия клиента; после остановки сервера он догоняет дедлайны при следующем запуске.
Чтение состояния также пересчитывает истёкшие вопросы. За простой не добавляется новое время.

Награды в исходном документе обозначены предварительными. Значения вынесены в `Game` в `appsettings.json`.
Пороги разрядов также предварительные: 0, 100, 300, 600, 1000, 1500 XP. Разряд и полоса вычисляются сервером.
Изменения этих чисел нужно согласовать с командой; уже выданные награды хранят фактические суммы и не пересчитываются.

## Что и где находится

- `Features/Game/GameService.cs`: создание/восстановление, выбор вопросов и сценария, приём выбора, дедлайны, итоги и награды.
- `ProgressService.cs`: статусы тем и ограничения доступа.
- `AttemptExpiryWorker.cs`: завершение попыток, к которым пользователь не вернулся.
- `GameOptions.cs`: экономика и разряды; `GameTime.cs`: единая точность времени PostgreSQL.
- `Features/Catalog`: лекции, отметки и XP за чтение.
- `frontend/js/api.js`: настоящие запросы, cookie и CSRF. Пути относительные; фронтенд работает и на Windows, и в опубликованном приложении.
- `frontend/js/views`: экраны входа, главной, теории, испытания, профиля и правил. Регистр имён импортов соответствует файлам для работы на Linux.
- `Persistence/DemoGameContent.cs`: три темы, по 10 вопросов босса и по 3 сценария с 4 шагами на тему.

Вопросы привязаны к версии в момент создания попытки; выбранные ID и порядок сохраняются.
Опубликованное содержание следует менять новой версией, а не редактированием записей действующей версии.
Административного API публикации и редактора пока нет. Иллюстрации аварий локальные; Markdown выводится с экранированием HTML.

## Согласованность данных

Изменяющие операции берут блокировку строки профиля пользователя в PostgreSQL и выполняются в транзакции.
Ответ, состояние попытки, первая отметка завершения темы, запись награды и баланс подтверждаются вместе.
Поэтому параллельные вкладки не создают две первые награды или две активные попытки.
Ограничения БД дополнительно проверяют соответствие темы, версии, вопроса и выбранного варианта.

Для каждого выбора фронтенд создаёт requestId. Сетевой повтор использует тот же ID.
В `AttemptChoices` сохраняются и неверные выборы QTE, а в `AttemptAnswer` — окончательный ответ шага.
Повтор одного выбора не списывает время второй раз. Обращение к уже истёкшему вопросу не отвечает за следующий.
Чужие попытки недоступны; до завершения API не раскрывает правильные варианты или пояснения.

Добавлены две миграции поверх исходной: `LearningTrials` и `TrialIntegrity`.
Они добавляют данные испытаний и новые связи, сохраняют старые записи и выводят их тему из существующей проверки.
Исторические успешные попытки получают отметки завершения тем без повторного изменения баланса.
Старые незавершённые заготовки, созданные до игрового API, закрываются с причиной `LegacyMigration`.

## Проверки

Набор интеграционных тестов использует настоящий PostgreSQL и отдельные временные базы.
Проверяются оба режима, повторный запрос, одновременный старт, награды разных режимов одной темы,
блокировка непрочитанных/закрытых тем, чужие попытки, серверные таймауты, фоновое завершение,
приоритет невиденных заданий, 100% курса и обновление БД с первоначальной схемы.

Ручной сценарий для браузера: регистрация → чтение → отметка → босс → победа → QTE → неверное действие →
обновление страницы → продолжение → повторная победа → история → выход. Проверить также узкий экран.
Как запускать автоматические проверки — в [development.md](development.md), контракты — в [api-map.md](api-map.md).
