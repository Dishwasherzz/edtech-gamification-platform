# Маскоты, скины и основа магазина

Бэкенд расширен 24 октября 2026 года. Папка `frontend/` не изменяется в этом обновлении.
Новые API позволяют будущему интерфейсу выбирать маскота, отображать его реакции, покупать и надевать скины.
Существующие поля профиля и попытки сохранены; добавлены отдельные поля внешнего вида.

## Что уже работает на сервере

- Каталог трёх маскотов: Искра, Ом, Реле. Выбор сохраняется в профиле.
- Реакции `Idle`, `Intro`, `CorrectAnswer`, `WrongAnswer`, `TimeWarning`, `Timeout`, `Victory`, `Defeat`, `Abandoned`.
- Отдельные варианты победы/поражения для Boss и Crisis: по два варианта для каждого маскота и режима.
- Каталог скинов, личный гардероб, выбор надетого скина, покупка за монеты и история покупок.
- Цена берётся из БД. Баланс, чек покупки и выдача предмета изменяются одной транзакцией.
- Дублирование запроса не приводит к повторному списанию. Два одновременных приобретения не могут потратить один и тот же баланс дважды.
- Покупки используют ту же блокировку строки профиля, что награды игры. Параллельная победа и покупка не теряют изменения друг друга.

Это серверная основа магазина: новые экраны, рисунки, анимации и сопоставление ключей с графикой добавляет фронтенд отдельным изменением.
`assetKey` — логический идентификатор ресурса, а не URL готовой картинки. Не нужно выполнять fetch по этому значению.
Например, `characters/engineer/copper` или `mascots/ohm/boss/victory-1` можно сопоставить с будущим SVG, PNG или анимацией.
У маскота без специальных реакций используется Idle, а при отсутствии и его — базовый assetKey персонажа.

## Начальные данные

| Тип | Ключ | ID | Цена |
|---|---|---|---|
| Скин | `default` | `60000000-0000-4000-8000-000000000001` | Бесплатен всем |
| Скин | `copper-engineer` | `60000000-0000-4000-8000-000000000002` | 30 монет |
| Скин | `neon-engineer` | `60000000-0000-4000-8000-000000000003` | 75 монет |
| Маскот | `spark` | `70000000-0000-4000-8000-000000000001` | Бесплатен |
| Маскот | `ohm` | `70000000-0000-4000-8000-000000000002` | Бесплатен |
| Маскот | `relay` | `70000000-0000-4000-8000-000000000003` | Бесплатен |

Цены примерные, их нужно согласовать с командой. Каталог и 51 запись реакций добавляет миграция `CosmeticsShop`;
для них не требуется запуск `--seed-demo`. Повтор миграции не создаёт дубли и не списывает монеты старых пользователей.
Базовый скин считается принадлежащим всем пользователям, даже без строки в `UserSkins`.
Покупка не надевает предмет автоматически: это отдельный осознанный выбор через `PUT /api/me/skin`.

## API

Все маршруты требуют входа по cookie. POST/PUT дополнительно требуют CSRF-токен, как и остальные операции проекта.
Идентификатор текущего пользователя сервер получает из cookie, а не из тела запроса.

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/shop/skins` | Базовые и продаваемые скины с ценами, признаками владения и надевания |
| GET | `/api/me/skins` | Личный гардероб, включая базовый скин и купленные предметы, снятые с продажи |
| GET | `/api/me/appearance` | Текущие `characterSkin` и `mascot` |
| PUT | `/api/me/skin` | `{ "skinId": "GUID" }` — надеть свой или базовый скин |
| GET | `/api/mascots` | Доступные маскоты |
| GET | `/api/mascots/{mascotId}` | Маскот и все его реакции с контекстами и вариантами |
| PUT | `/api/me/mascot` | `{ "mascotId": "GUID" }` — выбрать маскота |
| POST | `/api/shop/skins/{skinId}/purchase` | `{ "requestId": "GUID" }` — приобрести скин за текущую цену каталога |
| GET | `/api/me/purchases?page=1` | Свои покупки, по 20 на страницу, новые сначала |

Скин в каталоге: `id`, `key`, `name`, `description`, `assetKey`, `priceCoins`, `isStarter`, `isForSale`, `isOwned`, `isEquipped`.
Ответ покупки: `id`, `skinId`, `coinsSpent`, `coinsBalance`, `purchasedAt`, `isReplay`.
История покупки сохраняет уплаченную сумму, поэтому изменение цены не меняет старый чек.
`isReplay = true` означает повтор успешного запроса; `coinsSpent` в нём — цена исходного чека, а не новое списание.

Для одного действия создать requestId и сохранить его до получения определённого ответа.
При обрыве связи повторить запрос с тем же ID и тем же skinId. Если операция уже прошла, вернётся тот же чек.
Для другого скина нужен другой requestId. Ошибка недостатка монет не резервирует ID: после получения монет покупку можно повторить.

## Профиль и попытки

`GET /api/me` дополнительно возвращает:

```json
{
  "characterSkin": {
    "id": "60000000-0000-4000-8000-000000000001",
    "key": "default",
    "name": "Стандартный инженер",
    "assetKey": "characters/engineer/default"
  },
  "mascot": {
    "id": "70000000-0000-4000-8000-000000000001",
    "key": "spark",
    "name": "Искра",
    "description": "Поддерживает в учебных испытаниях.",
    "assetKey": "mascots/spark/idle"
  }
}
```

Это фрагмент ответа, остальные поля профиля остались прежними. `avatarKey` сохранён как отдельное старое поле;
выбор скина его не перезаписывает. Новые пользователи и старые профили без выбранных ID используют базовые значения.

В ответ попытки добавлены `characterSkin` и `mascot`. У маскота в попытке другой DTO:
`character` (описание персонажа), `event`, `context`, `reactionId`, `variant`, `assetKey`, `message`.
Пример события после победы: `event = Victory`, `context = Boss` или `Crisis`.
При поражении — `Defeat`, причина завершения остаётся в `finishReason` самой попытки.

Скин и маскот фиксируются при создании попытки. Изменение настроек влияет на следующие попытки;
старые ответы и активный бой сохраняют выбранных персонажей. Для старых попыток без этих полей используется базовый внешний вид.
Реакция вычисляется из сохранённых ответов и серверного времени, поэтому восстанавливается после обновления страницы.
Выбор варианта детерминирован: повторный запрос состояния одной и той же фазы не меняет анимацию случайным образом.

Приоритет реакции: победа/поражение/прерывание → вводный экран QTE → предупреждение при остатке не более 10 секунд →
последний таймаут → последний правильный/неправильный ответ → Idle.
Контекстные реакции имеют приоритет над `Any`; если их нет, используется общий вариант.

## Ограничения и ошибки

- `401`: нужен вход; `400 InvalidCsrfToken`: получить свежий CSRF-токен.
- `403 SkinNotOwned`: скин не принадлежит пользователю.
- `404 SkinNotFound` / `MascotNotFound`: неизвестный скин или недоступный маскот.
- `400 RequestIdRequired`: отсутствует непустой GUID покупки.
- `409 InsufficientCoins`: средств недостаточно, баланс не меняется.
- `409 SkinAlreadyOwned`: предмет уже принадлежит пользователю.
- `409 SkinNotForSale`: предмет снят с продажи.
- `409 RequestConflict`: requestId уже использован для другого скина.

Снять предмет с продажи можно полем `IsForSale` каталога. Уже купленный скин остаётся в гардеробе и его можно надеть.
Административного API изменения цен/каталога, продажи обратно, передачи предметов и платежей реальными деньгами нет.
Клиент не может установить цену, пополнить баланс или выдать предмет себе произвольным UserId.

## Проверка без изменения фронтенда

Открыть [Cosmetics.http](../requests/Cosmetics.http) в Rider. Для покупки сначала заработать монеты в существующем испытании.
Проверить: каталог → покупка → тот же запрос ещё раз → гардероб → надеть → выбрать маскота → новая попытка → победа/поражение.
Новый внешний вид появится в данных API; для показа графики потребуется отдельное подключение интерфейса.

Автоматические тесты проверяют владение, конкурентные списания, CSRF, изоляцию пользователей, чек со старой ценой,
совместную работу с наградами и реакции обоих режимов. Старые игровые тесты остаются частью набора.
