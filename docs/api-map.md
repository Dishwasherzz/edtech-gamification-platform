# Карта API

Первый этап реализует вход, профиль и учебный каталог. Всё через HTTP API, без серверных HTML-экранов.
В разработке машинный контракт доступен на `/openapi/v1.json`.

## Реализовано

| Метод | Путь | Вход | Результат |
|---|---|---|---|
| GET | `/api/auth/csrf` | Нет | `token`, `headerName`; устанавливает CSRF-cookie |
| POST | `/api/auth/register` | CSRF | Создаёт пользователя и профиль атомарно; 201 |
| POST | `/api/auth/login` | CSRF | Устанавливает auth-cookie; 204 |
| POST | `/api/auth/logout` | Cookie + CSRF | Выход; 204 |
| GET | `/api/me` | Cookie | Собственный профиль, XP и монеты |
| GET | `/api/courses` | Cookie | Опубликованные курсы |
| GET | `/api/courses/{courseId}/topics` | Cookie | Темы и количество прочитанных лекций |
| GET | `/api/topics/{topicId}` | Cookie | Тема, список лекций, метаданные опубликованных проверок |
| GET | `/api/lessons/{lessonId}` | Cookie | Markdown лекции и собственная отметка чтения |
| PUT | `/api/me/lessons/{lessonId}/completion` | Cookie + CSRF | Одна отметка чтения; повтор возвращает прежнюю дату |
| GET | `/health/live` | Нет | Работает ли процесс |
| GET | `/health/ready` | Нет | Доступна ли БД и применены ли миграции |

Тела запросов:

```json
{"email":"student@example.test","password":"Development123!","displayName":"Студент"}
```

```json
{"email":"student@example.test","password":"Development123!"}
```

Это примеры для локального теста, а не встроенный аккаунт. Для отметки чтения тело не используется;
можно отправить `{}`. Отметка не является проверкой знаний и не выдаёт награду.

`GET /api/me`:

```json
{
  "userId":"00000000-0000-4000-8000-000000000001",
  "displayName":"Студент",
  "avatarKey":"default",
  "totalXp":0,
  "coinsBalance":0
}
```

Пороговые значения уровня и разряда ещё не согласованы, поэтому эти вычисляемые поля пока не добавлены.
Метаданные проверки содержат только `id`, `title`, `mode`, `isRequired`; вопросы и ответы не выдаются.
В демо-данных первого этапа проверок пока нет.

## Следующий этап — пока не реализован

| Метод | Путь | Операция |
|---|---|---|
| POST | `/api/assessments/{assessmentId}/attempts` | Создать/вернуть активную попытку |
| GET | `/api/attempts/{attemptId}` | Получить состояние и текущий вопрос |
| PUT | `/api/attempts/{attemptId}/questions/{attemptQuestionId}/answer` | Принять один ответ и перейти дальше |
| POST | `/api/attempts/{attemptId}/abandon` | Завершить попытку без победы |
| GET | `/api/attempts/{attemptId}/result` | Итог и фактически начисленная награда |
| GET | `/api/me/attempts` | История с пагинацией |

Эти маршруты не зарегистрированы в приложении; они описывают направление разработки.
Административное редактирование материалов, публикация проверок и почтовое восстановление
доступа также реализуются отдельным этапом после уточнения требований.

Правила следующего этапа: проверка владельца, неизменяемая версия задания,
дедлайн по серверному времени, идемпотентный ответ, результат и награда в одной транзакции.
